目标：用户通过 Windows x64 安装包使用 Router，不需要自行安装 Node、Rust 或 C++ 开发工具。运行仍需 WebView2；接入 Worker 另需已安装且登录的 Codex。

当前状态：**准备中，不可据此发布二进制**。2026-10-08 在源码 `6e28eea` 上完成第一轮依赖盘点和 npm 安全检查，见 [升级前检查](third-party/review-2026-10-08.md)；随后经用户确认完成 [候选依赖更新与回归](third-party/dependency-update-2026-10-08.md)。无路由、Prompt、现有服务或用户配置变更。

## 隔离验收条件

必须使用没有开发工具、没有真实 Router 数据的独立 Windows x64 VM/测试机（或经确认可用的 Windows Sandbox）。不能仅删除 PATH 条目后宣称完成“干净机器验收”。当前开发机未发现 WindowsSandbox.exe，尚未提供独立环境；本轮未安装系统组件或创建虚拟机。

验收只使用虚构网关、假 Key 和测试配置，不复制真实 DPAPI 文件、Codex 登录态或会话历史。默认不调用“同步模型”“验证模型”“创建 Worker”等可能触网或产生费用的功能。真实 Codex/模型验收必须另列账号、请求范围和费用边界。

同一安装标识可能共用注册表、快捷方式和数据目录；在日常使用的 Windows 账号里换一个安装目录，不是安全的隔离验收。

## 验收矩阵（全部待执行）

| 场景 | 操作 | 通过标准 / 保留证据 |
| --- | --- | --- |
| 首次安装 | 标准用户安装候选，开发工具均未安装 | 无需 Node/Rust/MSVC；无需不合理提权；记录 Windows 版本、包 SHA256、安装目录和退出码 |
| WebView2 已存在 | 安装并从资源管理器打开 | 原生 UI 可交互，不依赖 Vite/localhost 前端服务；不出现额外黑框 |
| WebView2 缺失 | 在独立快照中允许下载引导程序后安装 | 提示清楚，成功安装后 UI 可用；网络断开时有可理解错误，不宣称离线可装 |
| 服务生命周期 | 使用空白/测试配置显式启动服务，关闭管理窗，再重开 | 服务状态真实，关闭管理窗不停止共享服务；未发模型请求 |
| 旧版升级 | 在同一独立账号先安装旧版候选，保存测试网关与假 Key，停止服务并关闭窗口，再安装新版 | 网关、模型选择和本账号假 Key 可用；新 runtime 路径有效；没有覆盖官方配置 |
| 运行中升级 | 仅在 VM 快照中测试管理窗/服务未停止的情况 | 安全阻止或明确要求停止，不能静默覆盖运行中的 runtime；如做不到，记录缺陷，不当作通过 |
| 卸载 | 停止服务并关闭窗口；分别测试保留数据和 UI 数据清除选项 | 程序/快捷方式删除；按照界面承诺保留网关/Key；验证实际文件及哈希，而非仅依赖提示文案 |
| 重装与恢复 | 在原独立 Windows 账号重装；恢复测试备份 | 假 Key 能在原账号解密、配置可读；不承诺跨账号 DPAPI 迁移；不自动启动真实请求 |
| Codex 不存在 | 未安装 Codex 时打开应用 | 网关管理可用；Worker 操作显示缺少 Codex，不崩溃 |

每个场景记录：候选哈希、初始快照、操作、预期/实际、结果、脱敏截图和残留。升级必须使用两个可辨认版本的候选；同版覆盖不能算升级验收。VM 测试的恢复只作用于该 VM，不触碰开发者的日常 Router。

## 用户安装与排障草案

以下是候选验收说明，不是“已发布安装包”的下载承诺：

1. 仅从本项目经确认的 GitHub Release 获取候选，核对 SHA256；未签名预览可能出现系统安全提示，不建议关闭系统防护。
2. 升级前在管理界面停止 Router，确认所有 Worker 空闲，再关闭窗口。关闭窗口本身不代表后台服务已停止。
3. 备份 `%LOCALAPPDATA%/CodexRouterPreview/state-v1`，只在本机受保护位置保留；其中包含敏感配置/加密凭据，不能上传 Issue。
4. 运行安装器后从开始菜单、快捷方式或资源管理器打开。正常使用不需要开发环境。
5. `DESKTOP_RUNTIME_MISSING`：程序目录的 runtime 不完整，核对候选后重装，不去安装全局 Node 作为替代。
6. 只看到 localhost 拒绝连接：确认打开的是安装后的桌面程序，而不是旧 Vite 浏览器地址。
7. WebView2 下载失败：检查网络并重新运行安装器；当前方案不是完全离线安装包。
8. 卸载前仍需停止服务；数据是否保留以该候选的实际验收结果为准。卸载不应被当作删除敏感数据的方法。
